## 项目概述

### 项目信息
- **项目名称**: Antigravity Claude Proxy
- **服务器IP**: YOUR_SERVER_IP
- **SSH密码**: YOUR_SSH_PASSWORD
- **SSH用户**: ecs-user
- **项目路径**: `~/antigravity-claude-proxy`

### 服务端口配置
- **Claude Proxy**: 8082 (主服务端口)
- **Clash 代理**: 8083 (HTTP代理)
- **Clash Dashboard**: 8084 (Web管理界面)
- **Clash SOCKS5**: 7891
- **OAuth回调**: 51121 (仅本地回环)

### 功能说明
将 Anthropic API 请求代理到 Antigravity Cloud Code 服务，支持 Claude 和 Gemini 模型：
- Claude: `claude-sonnet-4-5-thinking`, `claude-opus-4-5-thinking`
- Gemini: `gemini-3-flash`, `gemini-3-pro-low`, `gemini-3-pro-high`

## 代码修改记录

### 修改概述
为了让 Node.js 应用能够通过 Clash 代理访问 Google API，需要将原生 `fetch` 替换为支持代理的 `undici` 库。

### 修改的文件列表

#### 1. `src/oauth.js`
**修改位置**: 文件开头（第1-3行，import语句之前）

**添加内容**:
```javascript
import { ProxyAgent, fetch as undiciFetch } from "undici";
const createProxyFetch = () => {
  const proxyUrl = process.env.HTTPS_PROXY || process.env.HTTP_PROXY;
  if (proxyUrl) {
    const proxyAgent = new ProxyAgent(proxyUrl);
    return (url, options = {}) => undiciFetch(url, { ...options, dispatcher: proxyAgent });
  }
  return undiciFetch;
};
const fetch = createProxyFetch();
```

**修改原因**:
- OAuth流程需要访问 Google 的 Token 端点和 UserInfo 端点
- 使用 ProxyAgent 让请求通过 Clash 代理

### 代理支持工作原理

```javascript
const createProxyFetch = () => {
  // 1. 从环境变量读取代理地址
  const proxyUrl = process.env.HTTPS_PROXY || process.env.HTTP_PROXY;

  if (proxyUrl) {
    // 2. 创建 ProxyAgent（代理代理器）
    const proxyAgent = new ProxyAgent(proxyUrl);

    // 3. 返回包装后的 fetch 函数
    return (url, options = {}) => undiciFetch(url, {
      ...options,
      dispatcher: proxyAgent  // 使用代理发送请求
    });
  }

  // 4. 如果没有设置代理，直接使用 undici 的 fetch
  return undiciFetch;
};
```

**环境变量流向**:
```
PM2 ecosystem.config.cjs
  → HTTP_PROXY=http://127.0.0.1:8083
  → Node.js 进程环境变量
  → createProxyFetch() 读取
  → ProxyAgent 使用
  → 请求发送到 Clash (8083端口)
  → Clash 转发到真实目标
```

### 添加账号流程

#### 方法：SSH端口转发（推荐）

**步骤1 - 本地开启端口转发**:
```bash
# 在本地电脑新开一个终端
ssh -L 51121:localhost:51121 ecs-user@YOUR_SERVER_IP
# 输入密码: YOUR_SSH_PASSWORD

# 保持这个连接不要关闭！
```

**步骤2 - 连接服务器**:
```bash
# 在另一个终端
ssh ecs-user@YOUR_SERVER_IP
cd ~/antigravity-claude-proxy

# 设置代理环境变量（重要！）
export HTTP_PROXY=http://127.0.0.1:8083
export HTTPS_PROXY=http://127.0.0.1:8083

# 停止服务（添加账号时必须停止）
pm2 stop claude-proxy
```

**步骤3 - 添加账号**:
```bash
npm run accounts:add
```

**步骤4 - 浏览器授权**:
1. 终端会显示一个 Google OAuth URL
2. 在**本地浏览器**打开这个URL
3. 选择 Google 账号并登录
4. 点击"允许"授权
5. 浏览器跳转到 `http://localhost:51121/callback?code=...`
6. SSH端口转发会将请求传到服务器
7. 终端显示: `✓ Successfully authenticated: xxx@gmail.com`

**步骤5 - 继续添加**:
```
Add another account? [y/N]: y
```
输入 `y` 重复步骤4，添加更多账号

**步骤6 - 验证账号**:
```bash
npm run accounts:verify
```

预期输出:
```
✓ example1@gmail.com - OK
✓ example2@gmail.com - OK
✓ example3@gmail.com - OK
```

## 故障排查

### 问题1: 账号显示 "fetch failed"

**症状**:
```bash
npm run accounts:verify
# 输出: ✗ example@gmail.com - fetch failed
```

**排查步骤**:
```bash
# 1. 检查 Clash 是否运行
curl http://localhost:8084/ui/
# 如果失败，启动 Clash:
sudo systemctl start mihomo

# 2. 检查代理环境变量
echo $HTTP_PROXY
# 应该输出: http://127.0.0.1:8083

# 3. 如果没有设置，手动设置:
export HTTP_PROXY=http://127.0.0.1:8083
export HTTPS_PROXY=http://127.0.0.1:8083

# 4. 重新验证
npm run accounts:verify
```

**根本原因**:
- Node.js 原生 fetch 不支持代理环境变量
- 必须使用 undici 的 ProxyAgent

---

### 问题2: PM2 服务无法访问 Google API

**症状**:
```bash
pm2 logs claude-proxy
# 输出: Error: getaddrinfo ENOTFOUND oauth2.googleapis.com
```

**排查步骤**:
```bash
# 1. 检查 ecosystem.config.cjs 配置
cat ecosystem.config.cjs
# 确认包含:
#   HTTP_PROXY: 'http://127.0.0.1:8083'
#   HTTPS_PROXY: 'http://127.0.0.1:8083'

# 2. 重启 PM2
pm2 restart claude-proxy

# 3. 验证环境变量是否生效
pm2 env 0 | grep PROXY
```

### 问题5: Clash Dashboard 无法访问

**症状**:
浏览器访问 `http://YOUR_SERVER_IP:8084/ui/` 显示连接被拒绝

**排查步骤**:
```bash
# 1. 检查 Clash 是否运行
sudo systemctl status mihomo

# 2. 检查端口监听
netstat -tuln | grep 8084
# 应该显示: 0.0.0.0:8084 LISTEN

# 3. 检查配置文件
cat ~/.config/clash/config.yaml | grep external-controller
# 应该是: external-controller: 0.0.0.0:8084
# 不能是: external-controller: 127.0.0.1:9090

# 4. 重启 Clash
sudo systemctl restart mihomo

# 5. 检查防火墙（如果有）
sudo firewall-cmd --list-ports
# 确保 8084 端口开放
```
