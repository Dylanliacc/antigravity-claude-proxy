### 1. 服务器端配置

#### 1.1 代码修改

修改了 **4 个文件**以支持 HTTP 代理：

1. `package.json` - 添加 undici 依赖
2. `src/server.js` - 添加 ProxyAgent
3. `src/oauth.js` - 添加 ProxyAgent
4. `src/cloudcode-client.js` - 添加 ProxyAgent

**关键代码**:
```javascript
import { ProxyAgent, fetch as undiciFetch } from "undici";

const createProxyFetch = () => {
  const proxyUrl = process.env.HTTPS_PROXY || process.env.HTTP_PROXY;
  if (proxyUrl) {
    const proxyAgent = new ProxyAgent(proxyUrl);
    return (url, options = {}) =>
      undiciFetch(url, { ...options, dispatcher: proxyAgent });
  }
  return undiciFetch;
};

const fetch = createProxyFetch();
```

## 📝 解决的关键问题

### 问题 1: 账号验证失败

**症状**:
```
[CloudCode] fetchAvailableModels failed: fetch failed
```

**原因**: 缺少 HTTP 代理支持

**解决**:
- 修改 4 个文件添加 undici ProxyAgent
- 设置环境变量 `HTTP_PROXY` 和 `HTTPS_PROXY`

### 问题 2: Clash 启动失败

**症状**: `systemctl start mihomo` 找不到服务

**原因**: 服务器使用 `clash` 而不是 `mihomo`

**解决**:
- 创建 `clash-control.sh` 管理脚本
- 使用 `nohup` 后台运行 clash

### 问题 3: Claude Code OAuth 循环

**症状**: 配置文件不生效，仍要求 OAuth 认证

**原因**:
1. 配置文件路径错误（用了 `.config/claude-code` 而不是 `.claude`）
2. BASE_URL 包含了 `/v1` 后缀
3. 使用了错误的字段名（`ANTHROPIC_API_KEY` 而不是 `ANTHROPIC_AUTH_TOKEN`）

**解决**:
1. 使用正确路径: `%USERPROFILE%\.claude\settings.json`
2. BASE_URL 不包含 `/v1`
3. 使用 `ANTHROPIC_AUTH_TOKEN`
4. 完成一次 OAuth 认证（Claude Code v2.0.76 强制要求）

### 问题 4: 代理服务器 API key 验证

**误解**: 以为代理服务器需要验证 API key

**实际**: 代理服务器 **不验证** 客户端的 API key

**验证**: 使用 curl 测试，任意 API key 都能成功：
```bash
curl -H 'Authorization: Bearer sk-ant-dummy-fake-key' \
  http://YOUR_SERVER_IP:8082/v1/messages \
  -d '{"model":"claude-sonnet-4-5-thinking","messages":[...]}'
# 返回: {"role":"assistant","content":[{"text":"CONFIRMED"}]}
```

## 🎓 学到的经验

### 配置经验

1. **配置文件位置很重要**: Claude Code 使用 `~/.claude/settings.json`，不是 `~/.config/claude-code/settings.json`

2. **BASE_URL 后缀规则**:
   - 服务器端: `/v1`（因为是提供 API 服务）
   - 客户端: 不包含 `/v1`（Claude Code 会自动添加）

3. **OAuth 是必需的**: Claude Code v2.0.76 首次运行强制要求 OAuth，即使配置了环境变量

4. **代理不验证 API key**: 代理服务器只是转发请求，不验证客户端的 API key

### 调试经验

1. **使用 curl 测试**: 直接用 curl 测试可以排除客户端问题
2. **查看日志**: `pm2 logs` 和 `clash.log` 提供关键诊断信息
3. **分层验证**: 先验证服务器，再验证网络，最后验证客户端

### 文档经验

1. **及时记录**: 遇到问题立即记录，包括错误信息和解决方案
2. **分类整理**: 按功能分类文档（快速启动、完整配置、故障排查）
