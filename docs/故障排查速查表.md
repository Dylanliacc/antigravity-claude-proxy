## 🚨 紧急情况：服务完全不可用

### 症状
- 无法访问 http://YOUR_SERVER_IP:8082
- 所有请求超时

### 快速修复
```bash
ssh ecs-user@YOUR_SERVER_IP

# 1. 检查服务状态
pm2 status

# 2. 如果服务已停止，启动它
pm2 start claude-proxy

# 3. 如果服务状态异常，重启
pm2 restart claude-proxy

# 4. 查看错误日志
pm2 logs claude-proxy --err --lines 30

# 5. 如果仍然不行，完全重启
pm2 delete claude-proxy
pm2 start ecosystem.config.cjs
```

## 详细排查步骤

### #1: 账号显示 "fetch failed"

**症状**:
```bash
npm run accounts:verify
# ✗ example@gmail.com - fetch failed
```

**原因**: Node.js 无法通过代理访问 Google API

**诊断命令**:
```bash
# 1. 检查 Clash 是否运行
curl http://localhost:8084/ui/
# ❌ Connection refused → Clash 未启动
# ✅ 返回 HTML → Clash 正常

# 2. 检查环境变量
echo $HTTP_PROXY
# ❌ 空输出 → 未设置代理
# ✅ http://127.0.0.1:8083 → 已设置

# 3. 手动测试代理
export HTTP_PROXY=http://127.0.0.1:8083
curl -I https://www.google.com
# ❌ Connection refused → Clash 未监听
# ❌ Connection timeout → 代理节点失效
# ✅ HTTP/2 200 或 301 → 代理正常
```

**解决方案**:
```bash
# 方案A: 启动 Clash
sudo systemctl start mihomo
sleep 3
curl http://localhost:8084/ui/

# 方案B: 设置环境变量
export HTTP_PROXY=http://127.0.0.1:8083
export HTTPS_PROXY=http://127.0.0.1:8083

# 方案C: 重新验证
npm run accounts:verify

# 方案D: 如果仍然失败，检查代理节点
# 访问 http://YOUR_SERVER_IP:8084/ui/
# 切换到可用的代理节点
```

### #2: ENOTFOUND oauth2.googleapis.com

**症状**:
```bash
pm2 logs claude-proxy
# Error: getaddrinfo ENOTFOUND oauth2.googleapis.com
```

**原因**: PM2 环境变量未正确传递，或 Clash 未启动

**诊断命令**:
```bash
# 1. 检查 PM2 环境变量
pm2 env 0 | grep PROXY
# 应该输出:
# HTTP_PROXY: 'http://127.0.0.1:8083'
# HTTPS_PROXY: 'http://127.0.0.1:8083'

# 2. 检查 ecosystem.config.cjs
cat ecosystem.config.cjs | grep PROXY
# 应该包含:
# HTTP_PROXY: 'http://127.0.0.1:8083',
# HTTPS_PROXY: 'http://127.0.0.1:8083',

# 3. 检查 Clash
sudo systemctl status mihomo
```

**解决方案**:
```bash
# 方案A: 重启 PM2（重新加载环境变量）
pm2 restart claude-proxy

# 方案B: 确保 Clash 运行
sudo systemctl start mihomo

# 方案C: 完全重新部署
pm2 delete claude-proxy
pm2 start ecosystem.config.cjs

# 方案D: 验证环境变量生效
pm2 logs claude-proxy --lines 10
# 应该不再有 ENOTFOUND 错误
```

### #3: ECONNREFUSED 127.0.0.1:8083

**症状**:
```
Error: connect ECONNREFUSED 127.0.0.1:8083
```

**原因**: Clash 未启动或未监听 8083 端口

**诊断命令**:
```bash
# 1. 检查端口监听
netstat -tuln | grep 8083
# ❌ 无输出 → Clash 未运行
# ✅ tcp   0   0 127.0.0.1:8083   0.0.0.0:*   LISTEN → 正常

# 2. 检查 Clash 状态
sudo systemctl status mihomo

# 3. 检查配置文件
cat ~/.config/clash/config.yaml | grep ^port
# 应该输出: port: 8083
```

**解决方案**:
```bash
# 方案A: 启动 Clash
sudo systemctl start mihomo

# 方案B: 如果启动失败，查看日志
journalctl -u mihomo -n 50

# 方案C: 检查配置文件
vi ~/.config/clash/config.yaml
# 确保 port: 8083

# 方案D: 重启 Clash
sudo systemctl restart mihomo
```

### #4: OAuth Authentication timeout

**症状**:
```
Waiting for authentication (timeout: 2 minutes)...
Error: Authentication timeout
```

**原因**: SSH 端口转发未建立或断开

**诊断命令**:
```bash
# 在本地电脑执行：
# 1. 检查端口转发
lsof -i :51121
# ❌ 无输出 → 端口转发未建立
# ✅ ssh ... LISTEN → 端口转发正常

# 在服务器执行：
# 2. 检查 OAuth 服务器是否在监听
netstat -tuln | grep 51121
# ✅ tcp   0   0 127.0.0.1:51121   0.0.0.0:*   LISTEN
```

**解决方案**:
```bash
# 方案A: 重新建立端口转发（本地执行）
ssh -L 51121:localhost:51121 ecs-user@YOUR_SERVER_IP
# 保持这个连接不要关闭！

# 方案B: 检查是否有防火墙阻止
# （通常不需要，因为是 localhost）

# 方案C: 重新运行添加命令（服务器执行）
npm run accounts:add

# 方案D: 使用本地添加后上传的方式
# 见"部署配置文档.md"中的方法2
```

### #5: Connection refused 8082

**症状**:
```bash
curl http://YOUR_SERVER_IP:8082/health
# curl: (7) Failed to connect to YOUR_SERVER_IP port 8082: Connection refused
```

**原因**: Claude Proxy 服务未启动

**诊断命令**:
```bash
# 1. 检查 PM2 状态
pm2 status
# 查看 claude-proxy 的状态列

# 2. 检查端口
netstat -tuln | grep 8082
# ❌ 无输出 → 服务未运行
```

**解决方案**:
```bash
# 方案A: 启动服务
cd ~/antigravity-claude-proxy
pm2 start ecosystem.config.cjs

# 方案B: 如果服务显示为 "errored"
pm2 logs claude-proxy --err --lines 30
# 查看错误信息，针对性解决

# 方案C: 删除并重新创建
pm2 delete claude-proxy
pm2 start ecosystem.config.cjs

# 方案D: 测试服务
curl http://localhost:8082/health
```

### #6: Clash Dashboard 无法访问

**症状**:
```bash
curl http://YOUR_SERVER_IP:8084/ui/
# Connection refused
```

**原因**: external-controller 配置错误或 Dashboard 文件缺失

**诊断命令**:
```bash
# 1. 检查配置
cat ~/.config/clash/config.yaml | grep external-controller
# ❌ 127.0.0.1:9090 → 只监听本地，外部无法访问
# ✅ 0.0.0.0:8084 → 正确配置

# 2. 检查端口
netstat -tuln | grep 8084
# ✅ tcp   0   0 0.0.0.0:8084   0.0.0.0:*   LISTEN

# 3. 检查 Dashboard 文件
ls ~/.config/clash/dashboard/
# 应该有 index.html 等文件
```

**解决方案**:
```bash
# 方案A: 修改配置
vi ~/.config/clash/config.yaml
# 修改为: external-controller: 0.0.0.0:8084

# 方案B: 重启 Clash
sudo systemctl restart mihomo

# 方案C: 重新下载 Dashboard
cd ~/.config/clash
rm -rf dashboard
wget https://github.com/MetaCubeX/Yacd-meta/archive/gh-pages.tar.gz
tar -xzf gh-pages.tar.gz
mv Yacd-meta-gh-pages dashboard

# 方案D: 测试访问
curl http://localhost:8084/ui/
```

### #7: Invalid refresh token

**症状**:
```bash
npm run accounts:verify
# ✗ example@gmail.com - Invalid refresh token
```

**原因**: Token 被撤销或过期（用户在 Google 后台撤销了授权）

**诊断命令**:
```bash
# 查看账号配置
cat ~/.config/antigravity-proxy/accounts.json
# 检查 refreshToken 字段
```

**解决方案**:
```bash
# 方案A: 重新添加该账号
pm2 stop claude-proxy

# 本地开启端口转发
ssh -L 51121:localhost:51121 ecs-user@YOUR_SERVER_IP

# 服务器执行
export HTTP_PROXY=http://127.0.0.1:8083 HTTPS_PROXY=http://127.0.0.1:8083
npm run accounts:add
# 使用相同的 Google 账号重新授权，会自动更新 token

# 方案B: 删除无效账号
node src/accounts-cli.js remove
# 选择要删除的账号编号

# 方案C: 批量重新添加所有账号
node src/accounts-cli.js clear
npm run accounts:add
# 重新添加所有账号
```

### #8: Rate limit exceeded

**症状**:
```bash
curl http://localhost:8082/account-limits
# "isRateLimited": true
```

**原因**: 账号请求太频繁，被 Google 限流（这是正常的）

**说明**:
- 单个账号每分钟有请求限制
- 多账号池会自动切换到其他可用账号
- 限流会在几分钟后自动解除

**诊断命令**:
```bash
# 查看所有账号状态
curl http://localhost:8082/account-limits | jq '.accounts[] | {email, isRateLimited, isAvailable}'

# 查看可用账号数量
curl http://localhost:8082/account-limits | jq '.accounts[] | select(.isAvailable == true) | .email'
```

**解决方案**:
```bash
# 方案A: 等待（推荐）
# 限流会在 2-5 分钟后自动恢复
sleep 120
curl http://localhost:8082/account-limits

# 方案B: 添加更多账号
pm2 stop claude-proxy
export HTTP_PROXY=http://127.0.0.1:8083 HTTPS_PROXY=http://127.0.0.1:8083
npm run accounts:add
pm2 start claude-proxy

# 方案C: 降低请求频率
# 在客户端减少并发请求数量

# 方案D: 检查是否有账号仍然可用
curl http://localhost:8082/account-limits | jq '.accounts[] | select(.isAvailable == true)'
# 如果有可用账号，服务会自动切换
```

## 🛠️ 预防性检查清单

### 每次启动前检查
```bash
# ✅ 1. Clash 是否运行
curl http://localhost:8084/ui/ > /dev/null && echo "✅ Clash OK" || echo "❌ Clash 未运行"

# ✅ 2. 代理是否工作
export HTTP_PROXY=http://127.0.0.1:8083 && \
curl -I https://www.google.com 2>&1 | grep -q "HTTP" && \
echo "✅ 代理 OK" || echo "❌ 代理不工作"

# ✅ 3. 账号配置是否存在
test -f ~/.config/antigravity-proxy/accounts.json && \
echo "✅ 账号配置存在" || echo "❌ 无账号配置"

# ✅ 4. PM2 配置是否正确
grep -q "HTTP_PROXY.*8083" ecosystem.config.cjs && \
echo "✅ PM2配置 OK" || echo "❌ PM2配置错误"
```

### 完整健康检查脚本
```bash
#!/bin/bash
# 保存为 ~/check-proxy-health.sh

echo "🔍 Antigravity Proxy 健康检查"
echo "================================"

# 1. Clash
if curl -s http://localhost:8084/ui/ > /dev/null; then
    echo "✅ Clash Dashboard: 正常"
else
    echo "❌ Clash Dashboard: 异常"
fi

# 2. Clash 代理
if curl -s --proxy http://127.0.0.1:8083 https://www.google.com > /dev/null 2>&1; then
    echo "✅ Clash 代理: 正常"
else
    echo "❌ Clash 代理: 异常"
fi

# 3. Claude Proxy
if curl -s http://localhost:8082/health > /dev/null; then
    echo "✅ Claude Proxy: 正常"
else
    echo "❌ Claude Proxy: 异常"
fi

# 4. 账号状态
AVAILABLE=$(curl -s http://localhost:8082/account-limits | jq -r '.accounts[] | select(.isAvailable == true) | .email' | wc -l)
TOTAL=$(curl -s http://localhost:8082/account-limits | jq -r '.accounts | length')
echo "📊 可用账号: $AVAILABLE / $TOTAL"

echo "================================"
```

使用方法：
```bash
chmod +x ~/check-proxy-health.sh
~/check-proxy-health.sh
```

## 🆘 实在搞不定了？

### 终极重启大法
```bash
# 1. 停止所有服务
pm2 stop all
sudo systemctl stop mihomo

# 2. 等待10秒
sleep 10

# 3. 启动 Clash
sudo systemctl start mihomo

# 4. 等待 Clash 启动
sleep 5

# 5. 测试代理
curl --proxy http://127.0.0.1:8083 -I https://www.google.com

# 6. 启动 Claude Proxy
cd ~/antigravity-claude-proxy
pm2 start ecosystem.config.cjs

# 7. 等待服务启动
sleep 8

# 8. 测试服务
curl http://localhost:8082/health
curl http://localhost:8082/account-limits

# 9. 如果仍然失败，查看日志
pm2 logs claude-proxy --lines 50
```
